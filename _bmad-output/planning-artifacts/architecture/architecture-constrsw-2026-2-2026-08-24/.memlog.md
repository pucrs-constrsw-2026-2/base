- (decision by architect) AD-1 paradigma nomeado: malha de bounded contexts com BFF (DDD context map + Backend-for-Frontend). Camadas: IdP Keycloak; 9 contextos de dominio; oauth (catalogo/realm, nao e 10o dominio); BFF (unica composicao para a UI); frontend SPA unica. Binds a malha inteira. Prevents: 9 CRUDs desconectados, UI escolhendo servico, BFF dono de dominio. Rule: cada contexto e unidade de deploy e de contrato; UI so fala com BFF; BFF nao e dono de agregado.
- (direction) Alternativas de paradigma pesadas: monólito modular (rejeitada — layout ja e submodulos + 9 grupos); API Gateway puro sem BFF (rejeitada — UI faria join); event-driven mesh (adiada — v1 sync HTTP).
- (decision by architect) AD-1 dependencia: registros (employees, students, courses, rooms, resources) nao dependem de alocacao. professors -> employees. classes -> courses, professors, rooms, students (IDs). lessons -> classes, rooms e GET ReservationLine SALA. reservations -> rooms, resources, professors e GET ocupacao de lessons. BFF -> todos os 9 + Keycloak. frontend -> so BFF. oauth nao e runtime de dominio. Ciclo de leitura lessons<->reservations limitado a GET de profundidade 1. Prevents: classes persistindo Room copiada; BFF calculando sala efetiva; frontend importando OpenAPI dos 9.
- (decision by architect) AD-2 contrato: OpenAPI 3.1 YAML por contexto e a fonte da verdade (nao 3.2 — springdoc 3.1.0 e Nest swagger alinhados a 3.1). Paths = nome do submodulo em ingles prefixo /v1. Propriedades JSON usam tokens do glossario (salaEfetivaId, faixaId, employeeId, classId, lessonId, roomId). Proibido pessoa/evento/slot generico. Binds FR-25 NFR-CTR-1/3. Prevents: /funcionarios vs /employees; codegen sobrescrevendo lingua.
- (decision by architect) AD-2 envelope: RFC 9457 application/problem+json. Recusas de invariante (FR-13, FR-15, FR-23, FR-24, FR-30, FR-4, FR-11) usam status 409 (ou 422 validacao) com code igual ao FR (ex. FR-13) e type urn:closed-cras:recusa:FR-13. UI so mapeia code para refusal-banner; nao reimplementa colisao. 401/403 identidade; 404 ID inexistente. Binds FR-13/23/24/30 SM-5. Prevents: {message} ad hoc; UI inventando conflito.
- (decision by architect) AD-2 identidade de dados: IDs de agregado = UUID v4 string. faixaId = codigo canonico A-P (sem O, sem E1/E2). Prevents: int autoincrement divergente; slot ISO; copiar tabela de faixas em 9 repos.

- (decision by architect) AD-6 BFF: unica origem de browser. Dominios recusam Origin de frontend (sem CORS de SPA). BFF propaga Authorization Bearer (JWT do usuario) nas chamadas sync HTTP.
